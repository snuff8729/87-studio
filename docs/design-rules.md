# 87 Studio Design Rules

이 문서는 2026-10 리디자인(1~5단계, 컴포넌트 패스, 씬 템플릿·씬 팩·캐릭터 위치 작업)에서 정한 원칙을 모은 것이다. 새 화면을 만들거나 기존 컴포넌트를 고칠 때 **먼저 이 문서를 확인**하고, 여기서 벗어나야 하면 이유를 스펙에 남긴다.

## 0. 최우선 원칙

모든 컴포넌트 디자인과 배치는 아래 네 가지 의도를 **설명할 수 있어야** 한다. 설명할 수 없는 배치는 다시 설계한다.

1. **사용 흐름** — 사용자가 다음에 할 일이 바로 옆에 있다. 편집 → 실행 → 확인 순서가 화면의 배치 순서와 같다. (예: 좌측에서 프롬프트를 고치고 바로 아래 고정 푸터의 Generate를 누른다. Generate를 오른쪽 위에 두지 않는다.)
2. **일관성** — 같은 일은 어디서나 같은 모양·같은 위치·같은 동작이다. 새 패턴을 만들기 전에 아래 공용 패턴을 쓴다.
3. **정보의 흐름** — 기본값 → 덮어쓰기 → 최종 결과가 화면에서 따라 읽힌다. 덮어쓰지 않은 값은 "무엇을 따르는지"(예: `Default · Fixed C3`)를 보여준다. 가져오기·일괄 변경은 `현재 값 → 새 값`을 보여준다.
4. **시인성** — 지금 상태(선택, 필터, 저장, 진행, 오류)는 항상 보이고, 평소 상태(필터 없음 등)는 조용하다. 강조는 상태가 바뀌었을 때만 쓴다.

## 1. 색과 강조

- 다크 전용. 그래파이트 베이스 + Rose→Coral **단일 강조 계열**. 의미별로 다른 색(라임·파랑 등)을 섞지 않는다.
- `variant="brand"`(그라디언트)는 화면당 하나, **Generate에만**. 그 외 주 버튼은 `default`(solid `--primary`).
- 선택·활성 상태 = `--primary` 소프트 배경(`bg-primary/10~15` + 옅은 테두리). 같은 의미에 다른 표현을 쓰지 않는다.
- 파괴적 동작만 destructive 색. 경고·정보 표시는 강조색을 남발하지 않는다.

## 2. 화면 골격

| 화면 종류 | 골격 |
| --- | --- |
| 편집 화면 (빠른 생성, 워크스페이스) | `EditorShell`: 좌 = 편집 탭(Prompt·Chars·Refs·Params) + **고정 Generate 푸터**, 중앙 = 결과/선택한 대상, 우 = 히스토리. 리사이즈·접기, 모바일은 Edit/Result/History 전환 |
| 둘러보기 화면 (대시보드, 갤러리, 큐 등) | 제목·개수·액션은 **앱 헤더**(`usePageHeader` + `<HeaderActions>`). 본문에 큰 제목·설명 문단 없음. 전폭 + `p-4 md:p-6`, 가운데 좁은 칼럼 없음 |
| 라이브러리 (번들, 태그, 캐릭터 파츠) | `MasterDetail`: 좌 리사이즈 목록(검색 + ＋ New), 우 상세. 모바일은 목록 → 상세(뒤로가기 = 목록) |
| 큰 편집 다이얼로그 (씬 템플릿 등) | 화면 대부분 크기, 다중 패널, 고정 액션 푸터. 모바일은 전체 화면 단계 스택(뒤로가기) |

- 같은 대상이 한 화면에 두 번 나오지 않게 한다. 예전 워크스페이스는 좌측 Scenes 탭과 중앙 보드가 같은 씬을 중복해서 보여줬고, 이를 중앙 레일 + 보기로 바꿨다.
- 목록 → 상세 구조에서 목록은 "고르는 곳", 상세는 "고치는 곳"이다. 목록 안에서 편집하지 않는다(펼치는 아코디언 카드 대신 옆 패널에서 편집).

## 3. 액션 배치

- **주 액션은 작업하는 손 가까이**: 편집 패널의 고정 푸터, 다이얼로그의 고정 푸터.
- **헤더 액션**은 `HeaderButton` 한 크기(h-8, 13px, 아이콘 size-4). 화면이 좁으면 아이콘 버튼으로 줄이고(툴팁 + aria-label), **절대 줄바꿈하지 않는다**. 공간이 부족할 때 제목이 우선이고, 버튼이 아이콘으로 접힌다(뷰포트가 아니라 컨테이너 폭 기준).
- 자주 쓰는 동작은 아이콘 버튼, 드문 동작·파괴적 동작은 `⋯` 메뉴 안에 둔다.
- 행/카드의 메뉴는 **호버 `⋯` + 우클릭이 같은 항목**을 연다. 터치 기기에서는 `⋯`를 항상 보인다.
- 파괴적 동작은 확인 다이얼로그를 거친다. 파일 삭제처럼 되돌릴 수 없는 부수효과는 **체크박스로 선택, 기본 해제**(`DeleteFilesOption`)로 한다.

## 4. 만들기·추가

- 목록 안에 작은 입력칸을 끼워 넣지 않는다. **＋ 버튼에 붙은 Popover**(이름 + 필요한 최소 옵션 + Cancel/Add, Enter 제출·Esc 닫기)를 쓴다.
- 이름 말고 정할 게 없으면 묻지 않고 바로 만든다(예: 캐릭터 "Character N" 생성 → 선택 → 이름 칸 포커스).
- 만든 직후 새 항목을 **선택하고, 보이게 스크롤하고**, 접힌 그룹·필터가 가리면 풀어준다.
- 중복 이름 등 검증 오류는 입력 옆 인라인 메시지로 보여준다(토스트 남발 금지).

## 5. 검색·필터

- 평소에는 조용하게: 필터 버튼은 검색 입력 안 끝에 아이콘 하나만 둔다. 필터가 걸리면 강조 칩으로 바뀐다(`scene-search-filter.tsx`).
- 필터가 많은 화면(갤러리)은 **"＋ Filter" → 걸린 조건만 칩**(✕로 해제). 항상 보이는 배지 줄은 쓰지 않는다.
- 필터·정렬은 URL 파라미터에 둔다(뒤로가기·새로고침 유지). 보기 크기 같은 개인 취향은 localStorage에 둔다.
- 카드·썸네일 크기는 S/M/L 버튼 대신 **슬라이더**를 쓰고, 화면별로 저장한다.

## 6. 선택 모드 (여러 개 선택)

- 선택 중에는 **헤더가 선택 헤더로 바뀐다**: ✕ · 전체 선택 · "N selected" · 아이콘 액션 · `⋯`. 한 줄을 유지하고, 떠다니는 하단 바나 세로로 쌓이는 버튼은 쓰지 않는다.
- 선택 바는 화면에 **하나만** 띄운다(레일과 그리드에 같은 바를 중복하지 않는다).
- 같은 대상을 보여주는 여러 보기(레일·보드·선택 그리드)는 **선택 상태를 공유**한다. 썸네일로 고르는 선택 그리드는 보드와 일반 보기 모두에서 쓸 수 있다.
- 전체 선택과 일괄 동작은 **지금 보이는 항목에만** 적용된다. 필터·검색·접힌 그룹에 가려진 항목은 건드리지 않는다. 필터가 바뀌면 선택을 비운다.
- 파괴적이지 않은 일괄 동작 뒤에는 선택 모드를 유지한다. 삭제 뒤에는 종료한다.
- 새 일괄 동작은 이 선택 헤더에 붙인다(예: 일괄 태그, 팩 이동, 캐릭터 위치).

## 7. 기본값 → 덮어쓰기

- 설정은 `전역/캐릭터 기본값 → 씬 덮어쓰기` 순서로 흐른다. 씬 편집 UI의 첫 선택지는 **"Default"**이고, 라벨에 실제로 해석된 값을 같이 보여준다.
- 덮어쓴 값은 덮어쓰지 않은 값과 시각적으로 구분한다.
- 자동 동작보다 사용자의 명시적 선택이 항상 이긴다. 사용자가 이해하지 못하는 자동 동작은 만들지 않는다(예: 폭에 따라 레일이 자동으로 좁아지던 동작을 없애고 수동 토글만 남김).
- 추정한 값은 숨기지 않고 표시한다(예: "V5 · Full assumed").

## 8. 프롬프트 입력

- 프롬프트가 들어가는 모든 곳은 같은 CodeMirror 에디터를 쓴다(자동완성·하이라이트·가중치·번들·슬롯).
- 모든 프롬프트 입력에 같은 헤더 액션을 둔다: 태그 갤러리(북마크), 크게 보기. 한 곳에만 있는 기능을 만들지 않는다.
- 크게 보기 다이얼로그는 본문 높이를 다 채우고, 빈 영역을 클릭하면 에디터에 포커스가 간다.
- 인라인 에디터는 내용에 맞춰 늘어나되 최대 높이가 있다. 넘치면 스크롤이 생긴다는 것을 보이게 한다(페이드 등).
- 저장은 디바운스 자동 저장(약 800ms)이다. 다른 대상으로 전환하거나, 닫거나, Generate·Apply할 때 **반드시 flush**한다(pending-saves 레지스트리). 저장 상태가 보여야 한다.

## 9. 오버레이·다이얼로그·단축키

- 겹쳐 열리는 오버레이(다이얼로그 안의 태그 갤러리 등)는 **자체 닫기 버튼**을 가진다. Esc는 맨 위 하나만 닫는다.
- 모달이 열려 있으면 전역 단축키(Ctrl/Cmd+Enter Generate, Ctrl/Cmd+K 팔레트)는 동작하지 않는다. 입력용 Popover도 같은 가드를 따른다(`data-block-shortcuts`).
- 오버레이는 앱 셸 전체를 어둡게 덮는다. 일부만 밝게 남으면 버그다.

## 10. 목록·성능·스크롤

- 수십 개를 넘는 목록·그리드는 가상화한다(`@tanstack/react-virtual`). 그룹 헤더·선택·크기 조절이 그대로 동작해야 한다.
- 행 구성은 통일한다: 썸네일 · 이름(잘림 + 툴팁) · 인라인 컨트롤 · `⋯`.
- 방금 연 것, 방금 만든 것, 방금 고른 것은 스크롤해서 보여준다(미리보기 열기, 새 씬 추가, 팔레트 선택).
- ↑/↓로 목록 선택을 옮길 수 있다(히스토리를 쌓지 않는 replace 내비게이션).

## 11. 상태 표시·피드백

- 결과 알림은 토스트로, 입력 검증은 인라인으로 한다. 진행 중 작업은 진행 바(brand gradient)로 보여준다.
- 오류로 멈춘 상태는 사라지지 않고 남는다(예: 큐 에러 배너 + Retry/Skip).
- 빈 상태는 "다음에 할 일" 버튼을 함께 보여준다.
- 문구는 실제 동작과 일치해야 한다(삭제 시 파일이 지워지는지 남는지 정확히 쓴다).

## 12. 반응형·접근성

- 기준 폭은 데스크톱 1440, 모바일 390. 둘 다 확인한다.
- 모바일: 사이드 패널 → 시트/단계 화면, 목록 → 상세(뒤로가기 = 이전 단계), 터치 대상은 충분히 크게, 호버 전용 기능을 두지 않는다.
- 아이콘만 있는 버튼에는 `aria-label`과 툴팁을 단다. 드래그 UI는 키보드로도 조작할 수 있어야 한다(방향키, Shift는 큰 단위).

## 13. 구현 규칙

- shadcn/ui 컴포넌트를 먼저 쓰고, 없을 때만 커스텀으로 만든다. 아이콘은 hugeicons를 쓴다.
- 문구는 i18n(en + ko)으로 넣는다. 테스트 선택자는 문구가 아니라 role/data 속성을 쓴다.
- 보기 취향(패널 폭, 접힘, 크기, 토글)은 `87studio-<기능>:<id>` localStorage 키에 저장한다. 공유·영속 데이터는 DB에 저장한다.

## 14. 새 컴포넌트 체크리스트

- [ ] 이 컴포넌트는 사용자의 어느 흐름 단계에 있나? 다음 행동이 바로 옆에 있나?
- [ ] 이미 있는 공용 패턴(헤더 액션, ＋ Popover, 선택 헤더, 검색+필터, MasterDetail, PromptEditorHeader)으로 해결되나?
- [ ] 기본값/덮어쓰기/최종값이 화면에서 읽히나?
- [ ] 현재 상태(선택·필터·저장·진행·오류)가 보이고, 평소 상태는 조용한가?
- [ ] 좁은 폭에서 줄바꿈 없이 접히나? 모바일 390에서 동작하나?
- [ ] 파괴적 동작은 확인을 거치고, 되돌릴 수 없는 부수효과는 기본 꺼짐인가?
- [ ] 편집 중인 값이 전환·닫기·실행 시 저장되나?
